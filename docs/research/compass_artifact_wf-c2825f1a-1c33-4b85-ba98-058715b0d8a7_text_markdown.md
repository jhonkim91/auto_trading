# 주식 자동매매 프로그램 개발 종합 기술 조사 보고서 (KRX·2024–2026 기준)

## TL;DR
- 한국 주식(KRX) 환경에서 개인이 무료로 완전 자동매매를 구축하는 최적 경로는 **한국투자증권 KIS Developers REST/WebSocket API(무료, REST 실전 초당 20건)** + **pykrx·FinanceDataReader(무료 일봉 데이터)** + **backtrader/vectorbt 백테스팅** + **python-telegram-bot 제어/알림**이며, 반드시 **모의투자 → 소액 실전** 순으로 검증해야 한다.
- 기술적 지표(RSI·MACD·볼린저밴드 등)는 단독 신호가 아니라 "상태 표시등"으로 다중 확인에 써야 하며, KRX·코스닥처럼 변동성이 큰 시장에서는 래리 윌리엄스 **변동성 돌파 전략**이 코드 몇 줄로 검증 가능한 대표적 실전 전략이다. 리스크 관리(손절·포지션 사이징·Half Kelly·MDD 관리)가 전략 자체보다 생존에 더 결정적이다.
- LSTM·강화학습 같은 AI 기법은 "가격을 직접 예측"하면 전일 종가 복제 같은 함정에 빠지므로, 신호 보조·변동성 예측 용도로 제한적으로 쓰는 것이 현실적이다.

## Key Findings

### 1. 상용 자동매매 기술과 증권사 API 지형
- 국내 증권사 Open API는 크게 두 부류다. **REST/WebSocket 방식**(한국투자증권 KIS, 이베스트투자증권 신규 REST)과 **Windows 전용 COM/OCX/DLL 방식**(키움 OpenAPI+, 대신 CYBOS Plus/Creon, 이베스트 구 xingAPI)이다. REST 방식은 OS 제약이 없어 리눅스·클라우드에서도 구동 가능해 신규 개발의 표준이 되고 있다.
- 증권사별 특징·유량 제한(퀀티랩 "증권사 API 장단점 비교" 등):
  - **키움 Open API+**: 문서화가 좋고 시장점유율 1위이나 응답이 비동기라 불편하고 PyQt 필요. 퀀티랩 블로그 명시 — "키움증권 Open API: 1초에 5회로 제한하며, 제 경험상 1시간에 1000회로 제한하고 있습니다." 키움 공식 안내상 국내 주식주문·신용주문·선물옵션주문은 모두 1초당 5회 제한이며 초과 시 에러 -308을 리턴한다.
  - **대신 Creon**: 동기 방식이라 사용이 편함. 퀀티랩 — "대신증권 크레온 API: 시세 조회의 경우 15초에 60건, 실시간 조회의 경우 최대 400건으로 제한되어 있고, 주문 관련 조회의 경우 15초에 최대 20건으로 제한됨."
  - **이베스트 xingAPI**: 수수료가 싸고 제한이 가장 약함. 퀀티랩 — "이베스트투자증권 Xing API: 모의서버의 경우 1초에 10건으로 제한되어 있습니다 … 요청 제한은 Xing API가 가장 제한이 약하고." 단 TR/Res 파일 구조가 비직관적.
  - 세 곳 모두 Windows 환경·자동로그인 지원.
- 글로벌에서는 **TradingView**(Pine Script 전략·알림), **MetaTrader 4/5**(MQL, FX·CFD 중심)가 대표적이며, 백테스팅·시그널 생성에 널리 쓰인다.

### 2. 기술적 지표 — 원리와 활용
- **RSI(14)**: 평균 상승분/평균 변동분 비율. 70 이상 과매수, 30 이하 과매도가 표준 임계치이나, 강세장에서는 RSI 70에서 매도하면 큰 상승을 놓친다(변동성 큰 시장은 80/20 적용 권장). 다이버전스(가격-지표 불일치)는 박스권·추세전환 구간에서 유효.
- **MACD(12,26,9)**: 12일 EMA−26일 EMA, 시그널은 9일 EMA. MACD가 시그널을 상향 돌파=골든크로스(매수), 하향=데드크로스(매도). 추세 "확인" 도구이지 예측 도구가 아니며 횡보장에서 잦은 거짓신호.
- **볼린저밴드(20, ±2σ)**: John A. Bollinger(1950년생)가 1980년대 초 Financial News Network 자본시장 분석가로 재직 중 개발했으며(영문 Wikipedia 'John Bollinger'·'Bollinger Bands': "developed by John Bollinger in the 1980s"), 2011년 Market Technicians Association의 Dow Award를 수상했다. 그의 저서 *Bollinger on Bollinger Bands*(2001, McGraw Hill)는 11개 언어로 번역되었다. 밴드폭 급축소(스퀴즈)는 큰 변동 임박 신호. 다만 추세장에서는 밴드를 타고 지속 상승/하락하므로 "상단=꼭지" 공식은 위험. 거래량·RSI·MACD와 결합 필요.
- 기타: **이동평균선(MA/EMA)**(골든·데드크로스), **스토캐스틱**(%K·%D, 과매수/과매도), **ATR**(변동성 측정→손절폭·포지션 사이징 핵심 입력), **VWAP**(거래량가중평균, 기관 체결기준·일중 단타), **OBV**(누적 거래량으로 수급), **피보나치 되돌림**(38.2/50/61.8% 지지·저항).
- 핵심 교훈(머니레시피 백테스트): "RSI 30 이하 매수" 단순전략은 적용 구간에 따라 성과가 완전히 달라지며, 파라미터 미세튜닝(RSI 14→17 등)은 과거 구간 과최적화일 뿐. 지표는 "매매 버튼이 아니라 질문 목록"으로 다뤄야 한다.

### 3. 매매 전략
- **단기**: 모멘텀(상승 종목 추격), 브레이크아웃/변동성 돌파, 평균회귀(밴드 복귀 매수), 스캘핑(초단타, 수수료·슬리피지가 관건).
- **변동성 돌파(래리 윌리엄스)**: 당일 목표가 = 당일 시가 + (전일 고가−전일 저가) × K. 돌파 시 매수, 익일 시가 청산. K(노이즈비율)는 추세가 강할수록 낮게, 횡보일수록 높게 설정. 코스닥·암호화폐처럼 변동성 크고 비효율적 시장에서 잘 작동하고, 외환·금·원유에서는 수익곡선이 망가진다.
- **장기**: 추세추종, 골든/데드크로스, 포트폴리오 리밸런싱(정해진 시간에 분할 매매로 시장충격 최소화).
- **리스크 관리**:
  - 손절매: 손익 비대칭 원리(50% 하락 후 원금 회복엔 100% 상승 필요) 때문에 필수. 진입과 동시에 손절 주문 세팅.
  - 포지션 사이징: ATR 기반 또는 계좌 대비 고정 위험비율(예: 거래당 1~2%).
  - 켈리 공식: f* = (bp−q)/b. 승률 60%·1:1 배당이면 20% 베팅이 최적. 단 Full Kelly는 변동성이 극심해 자산 50%가 증발할 수 있으므로 실전은 **Half Kelly(수익 75% 유지·변동성 50%로 감소)** 또는 Quarter Kelly 권장.
  - MDD(최대낙폭) 관리: 백테스트·실전 모두 MDD를 핵심 지표로 모니터링.

### 4. 백테스팅 라이브러리
- **backtrader**: 이벤트 드리븐, 라이브 트레이딩·브로커 연동 가능, Pythonic해서 진입 장벽 낮음. 다만 커뮤니티 유지보수가 느려졌고 대용량·HFT엔 느림.
- **vectorbt**: NumPy/Numba 기반 벡터화로 압도적 속도(수백만 거래 1초 내), 파라미터 스윕·다자산 연구에 최적. 학습곡선 가파르고 체결현실성(슬리피지·주문관리)은 직접 구현 필요. PRO(유료)는 현실적 체결 시뮬레이션 강화.
- **zipline(-reloaded)**: 팩터·롱숏 주식 연구의 Pipeline API가 강점이나 설치가 까다롭고 신규 프로젝트 기본 선택은 아님.
- 2026년 흐름: 연구속도 중시→vectorbt/zipline, 실전 체결·프로덕션→NautilusTrader, 통합 플랫폼→QuantConnect(LEAN). KIS 공식 레포도 백테스터로 QuantConnect Lean을 채택.

### 5. AI/ML 자동매매
- LSTM으로 "다음날 종가"를 직접 예측하면, 모델이 "오늘 종가≈어제 종가"라는 무의미한 해를 학습하는 전형적 함정에 빠진다(코딩애플 칼럼). 비정상(non-stationary) 시계열을 수익률·변동폭으로 변환해 stationary화하는 전처리가 중요.
- 더 유망한 활용: 가격 자체가 아닌 **상승/하락 분류**, **변동성 예측**. 한국 사례로 김겨레·한희준(2024, 금융연구 38(3)) "Multi-Input LSTM"이 표준 HAR 모형보다 VKOSPI 변동성 예측력이 우수했고, 수급·자금흐름 변수가 중요 역할.
- 강화학습은 포지션·실행 최적화에 연구되나, 실거래 검증·과적합 위험이 커 신중해야 한다.

### 6. 한국투자증권 KIS Developers API (상세)
- **무료**: 공식 포털 요금안내 — "기본적으로 제공하는 API 유량에 대해서는 0원이며 추가 유량을 원하시는 고객을 위하여 향후 별도 과금정책을 정하여 포털을 통해 공지 드릴 예정"이며 별도 이용료 없음. 서비스 이용기간은 신청일로부터 **1년**, 만료 30일 전부터 갱신 가능(갱신 시 APP Key/Secret 재발급). 3개월 이상 미거래 시 자동 해지될 수 있음. 모의투자 계좌는 별도 신청(실전 최대 89계좌·모의 최대 2계좌).
- **인증(OAuth2)**: APP Key/APP Secret으로 `/oauth2/tokenP` 호출 → access_token 발급. 토큰 **유효기간 24시간(expires_in 86400초)**, **재발급은 1분당 1회**(공식 레포 README — "토큰 재발급 - 1분당 1회 발급됩니다"; 토큰 발급 자체도 초당 1건 제한, 2023-10-27 시행). 잦은 발급 시 이용제한될 수 있어 토큰을 파일(token.dat)에 저장·재사용하고 6시간 주기 갱신을 권장. WebSocket은 별도 **접속키(approval_key)** 발급.
- **REST 호출 제한**: 실전투자 **초당 20건**(계좌/앱키 단위), 모의투자 **초당 5건**(KIS Developers 팀 답변 기준; 일부 구 공지엔 초당 2건). 슬라이딩 윈도우 방식이라 경계 몰림 주의. 다종목 처리 시 배치 크기·지연을 동적 계산해 초당 20건 이하 유지하는 패턴 필수.
- **WebSocket 실시간**: 1세션당 실시간체결가(H0STCNT0)+호가(H0STASP0)+예상체결+체결통보 **합산 41건**까지 등록 가능(국내·해외·파생 전 상품 합산). 체결통보(H0STCNI0/H0STCNI9)는 HTS ID 단위. 데이터는 `|` 구분 문자열, 체결통보는 AES256 복호화 필요.
- **국내주식 주요 TR_ID**:
  - 현재가: `FHKST01010100` (`/uapi/domestic-stock/v1/quotations/inquire-price`)
  - 일/주/월봉: `FHKST03010100` 등 기간별 시세(`FID_PERIOD_DIV_CODE` D/W/M)
  - 현금 매수: 실전 `TTTC0802U` / 모의 `VTTC0802U`
  - 현금 매도: 실전 `TTTC0801U` / 모의 `VTTC0801U`
  - 정정·취소: 실전 `TTTC0803U` / 모의 `VTTC0803U` (`/order-rvsecncl`)
  - 잔고조회: `TTTC8434R` (보유종목·평가손익), 매수가능조회 `TTTC8908R`
  - 체결내역: `TTTC8001R` (`/inquire-daily-ccld`)
  - 주문 파라미터: ORD_DVSN(00 지정가/01 시장가 등), ORD_QTY, ORD_UNPR. 주문 시 hashkey 발급 권장.
- **샘플코드/SDK**: 공식 `github.com/koreainvestment/open-trading-api`(kis_auth.py·국내외 상품별 예제, strategy_builder·backtester 포함). 커뮤니티 라이브러리 **python-kis**(Soju06, `pip install python-kis`, Python 3.11 기준, 자동 토큰관리·웹소켓 재연결), Java용 **finance.kis_api**(youhogeon, 유량제어 내장).

### 7. 무료 데이터 API
- **pykrx**: KRX·네이버 스크래핑. 일별 시세, 투자자별 매매(당일 18시 이후), 공매도, 지수, 시총. 국내 특화·종류 풍부하나 스크래핑이라 갱신지연·과도호출 자제 필요.
- **FinanceDataReader**: 국내외 통합. 종목 리스팅(KRX/KOSPI/KOSDAQ/KONEX, NASDAQ 등), 개별 시세, 지수, 환율, 암호화폐, 재무제표(NAVER 소스). 국내장은 야후보다 정확. `pip install finance-datareader`.
- **OpenDartReader / OPEN DART**: 금융감독원 전자공시. 재무제표·공시·지분. 개인 인증키 무료, **일 10,000건 제한**. 추가로 분당 호출 한도 존재 — dart-fss 공식 문서: "Open DART 및 DART 홈페이지의 경우 분당 1000회 이상 요청시 서비스가 제한될 수 있음"(github.com/josw123/dart-fss). 종목코드→고유번호 변환 등을 OpenDartReader가 자동화.
- **NAVER 금융 크롤링**: 보조 수단. 과도 트래픽은 법적 리스크.
- **글로벌 무료**: **yfinance**(무료·무제한이나 비공식 스크래핑이라 수시 중단 위험), **Alpha Vantage**(Alpha Vantage 공식 지원 페이지 — "free stock API service covering the majority of our datasets for up to 25 requests per day", 기본 무료 티어 분당 5회; NASDAQ 라이선스 데이터 제공사로 실시간·15분 지연 미국 시장 데이터는 프리미엄 전용, 기술지표 50종+ 내장), **Twelve Data**(무료 일 800건, 4시간 지연, WebSocket은 유료), **Finnhub**(분당 60건, 미국 실시간). 대부분 무료 티어는 15~20분 지연.

### 8. 텔레그램 봇 제어 시스템
- **라이브러리**: `pip install python-telegram-bot --upgrade` (v20+, **모든 네트워크 I/O가 async/await**로 전환). `ApplicationBuilder().token(...).build()` → `CommandHandler`/`CallbackQueryHandler`/`MessageHandler` 등록 → `run_polling()`. 봇 토큰은 BotFather `/newbot`로 발급, chat_id는 `getUpdates`로 확인.
- **활용 패턴**: ① 매매신호·체결 알림 전송(send_message), ② `/auto` `/semi` 완전·반자동 전환, ③ `/portfolio` 보유·평가손익 리포트, ④ `/pnl` 수익률 보고, ⑤ `/liquidate` 긴급 전체청산.
- **인라인 키보드**: `InlineKeyboardMarkup`+`CallbackQueryHandler`로 [매수][매도][청산][현황] 버튼형 대화 제어. `edit_message_text`로 기존 메시지 갱신.
- **보안**: 허용된 chat_id(또는 user_id) 화이트리스트로 본인만 명령 가능하도록 핸들러 첫 줄에서 검증, 미허용 시 무시. 토큰·키는 코드 하드코딩 금지(.env/yaml 분리). 동시성 처리 시 JobQueue 사용 권장.

### 9. 시스템 아키텍처 & 기술 스택
- **권장 스택(버전 포함)**: Python 3.11 / requests≥2.32 / websocket-client≥1.8 또는 websockets / pandas·numpy / FinanceDataReader·pykrx / backtrader·vectorbt / APScheduler 3.11.x / python-telegram-bot 20+ / SQLAlchemy / PyYAML / cryptography≥43(웹소켓 복호화) / TA-Lib 또는 pandas-ta(지표).
- **계층 구조**: (1) 데이터 수집(REST 일봉/분봉 + WebSocket 실시간) → (2) 전략·시그널 엔진(지표·룰) → (3) 리스크 관리(포지션 사이징·손절·MDD) → (4) 주문 실행(KIS 주문 API, 유량제어) → (5) 저장·로깅 → (6) 텔레그램 알림·제어.
- **스케줄링**: 단순 반복은 `schedule`, 프로덕션은 **APScheduler** 권장(cron 트리거로 평일 09:00~15:30 장중 실행, SQLAlchemyJobStore로 SQLite에 작업 영속화→재시작 후 복구). 장 시작/마감, 토큰 갱신, 리밸런싱 등 작업을 분리.
- **데이터 저장소**: 단일 머신·중소 데이터는 **SQLite**(파일 기반·설정 불필요)로 충분. 다중 프로세스 동시쓰기·대용량·원격 접근이면 **PostgreSQL**. APScheduler 잡스토어도 동일 기준.
- **로깅**: Python `logging` 표준 모듈로 파일+콘솔 핸들러, 레벨 분리(DEBUG/INFO/ERROR), 회전 로그(RotatingFileHandler), 모든 주문·체결·오류·API 응답 기록(감사 추적).
- **개발 순서(모의→실전)**: ① KIS 서비스 신청·모의계좌 발급 → ② 모의투자 앱키로 토큰·조회 테스트 → ③ 과거 데이터로 백테스트(backtrader/vectorbt) → ④ 모의투자에서 실시간 페이퍼 트레이딩(변동성 돌파 등) → ⑤ 소액 실전 → ⑥ 점진적 규모 확대. KIS 공식 레포에도 `ka.auth(svr="vps")`(모의) → `svr="prod"`(실전) 전환 구조 제공.

## Recommendations
1. **즉시(1~2주)**: 한국투자증권 계좌 개설 → KIS Developers 서비스 신청(실전+모의 2계좌) → APP Key/Secret 발급. Python 3.11 가상환경에 위 스택 설치. 공식 `open-trading-api` 레포 클론, kis_auth.py로 토큰 발급(token.dat 저장·24시간 유효·6시간 갱신) 성공이 첫 관문.
2. **데이터·백테스트(2~4주)**: FinanceDataReader+pykrx로 KOSPI/KOSDAQ 일봉 적재(SQLite). 변동성 돌파(K=0.5 시작) 또는 이동평균 크로스 전략을 backtrader로 백테스트. **MDD·승률·손익비**를 핵심 지표로 평가. 임계 기준: 거래비용(수수료+슬리피지) 반영 후에도 샤프>1, MDD가 감내 범위 내일 때만 다음 단계.
3. **모의 실거래(4~8주)**: 모의투자 앱키로 WebSocket 실시간 수신(41건 한도) + 장중 APScheduler 자동 실행 + 텔레그램 알림/제어(화이트리스트 보안) 통합. 최소 1~2개월 페이퍼 트레이딩으로 백테스트와 실거래 괴리(체결지연·미체결) 확인.
4. **소액 실전(이후)**: 페이퍼 성과가 백테스트와 크게 어긋나지 않으면 소액 실전 전환. 포지션 사이징은 **Half Kelly 이하**, 거래당 위험 1~2%, 진입과 동시 손절 세팅. 일 손실 한도·MDD 한도 도달 시 `/liquidate` 자동·수동 청산 룰 명시.
5. **AI 도입은 최후**: 규칙기반 시스템이 안정적으로 수익·생존을 입증한 뒤에만 LSTM(분류/변동성)·강화학습을 신호 보조로 추가. 가격 직접 예측은 지양.
- **단계 변경 트리거**: 모의/실전에서 MDD가 백테스트의 1.5배를 초과하거나 실거래 슬리피지가 가정의 2배를 넘으면 규모를 줄이고 전략·체결 로직을 재점검.

## Caveats
- KIS 모의투자 REST 제한은 출처 간 상충(초당 5건 vs 2건)하며, 모의 시스템은 한국투자증권이 직접 운영하지 않아 실전과 동작·유량이 다를 수 있다. 연속 호출이 많은 파라미터 최적화는 실전 계좌 권장.
- pykrx·yfinance·NAVER 크롤링은 비공식 스크래핑으로 사이트 변경 시 중단되거나 약관 위반 소지가 있다. 상업적 이용 시 각 제공처 약관 확인 필수.
- 토큰 발급 1분 제한·EGW00133류 오류, 실시간 41건 한도 등 세부 정책은 수시 변경되므로 배포 전 공식 포털 최신 문서 확인 필요.
- 모든 백테스트는 생존편향·과최적화·미래참조(look-ahead) 위험이 있으며, 과거 성과가 미래를 보장하지 않는다. 변동성 돌파 등 특정 전략은 시장·종목군에 따라 성과가 극단적으로 갈린다.
- 본 보고서는 기술 조사이며 투자 권유가 아니다. 자동매매는 원금 손실 위험이 있고, 시스템 장애·네트워크 단절·오주문 위험을 항상 대비해야 한다.
